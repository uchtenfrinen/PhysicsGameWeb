# Перенос проекта «WPF Physics» в Unity

Этот документ описывает исходный WPF-проект и как воспроизвести его в Unity. Используйте его как единый источник правды при генерации кода и сцен.

---

## 1. Назначение приложения

**Интерактивный физический конструктор**: пользователь выбирает раздел физики → установку (демо) → настраивает параметры слайдерами → смотрит анимацию установки, графики зависимостей и текстовые объяснения. Есть опциональный чат с нейросетью (Groq API) для пояснений по текущей установке.

**Целевая платформа Unity**: 2D/3D по выбору; для большинства установок достаточно **2D (Canvas + камера orthographic)** или **UI Toolkit + отрисовка линий/спрайтов**.

---

## 2. Архитектура WPF (что переносить как есть, что переписать)

| Слой WPF | Содержимое | Unity |
|----------|------------|--------|
| **`Physics/*.cs`** | Чистая логика: формулы, шаг симуляции, без UI | **Переносится почти без изменений** в `Assets/Scripts/Physics/` (убрать зависимости от `System.Windows` если есть). |
| **`*ViewModel.cs`** | `INotifyPropertyChanged`, команды, таймеры анимации | **MonoBehaviour** или отдельные классы + **Unity Events** / **UniRx** / обычные C# события. |
| **`*Canvas.cs`, `*ChartControl.cs`, `*SchemeControl.cs`** | `DrawingContext`, `InvalidateVisual`, привязка к ViewModel | **LineRenderer**, **Mesh**, **UI Image + RectTransform**, **GL.Lines** (осторожно), или плагин графиков. |
| **`*View.xaml` + `.xaml.cs`** | Разметка, слайдеры, кнопки, привязки | **Unity UI (uGUI)** или **UI Toolkit** (UXML/USS). |
| **`MainWindow.xaml`** | Контейнер, навигация по `Content` | **Сцена с Canvas** или **одна сцена + панели** / **Addressables** для «экранов». |
| **`Navigation/PhysicsSection.cs`** | Каталог разделов и установок | **ScriptableObject** или статический класс с тем же JSON/структурой. |
| **`Services/GroqService.cs`** | HTTP к Groq, ключ из файла/env | **`UnityWebRequest`** или `HttpClient` (IL2CPP — проверить совместимость), ключ в **PlayerPrefs** / **ScriptableObject** / env (Editor). |

## 3. Навигация и идентификаторы установок

Главное окно подставляет `UserControl` по `args.Setup.Id`. **Сохраните те же строковые id**, чтобы не путать логику и сохранения.

### Разделы и установки (из `Navigation/PhysicsSection.cs`)

- **mechanics** (Механика)
  - `inclined_plane` — Груз на наклонной плоскости
  - `free_fall` — Свободное падение
  - `projectile` — Движение тела, брошенного под углом
  - `spring` — Пружина с грузом
- **hydro** (Гидростатика)
  - `buoyancy` — Плавание тела (Архимед)
  - `communicating_vessels` — Сообщающиеся сосуды
- **heat** (Теплота и МКТ)
  - `ideal_gas` — Уравнение состояния идеального газа
- **electricity** (Электричество)
  - `ohm_law` — Закон Ома для замкнутой цепи
  - `resistors_connection` — Резисторы: последовательно/параллельно
  - `charge_in_field` — Заряд в однородном поле
- **optics** (Оптика)
  - `thin_lens` — Тонкая линза
  - `refraction_at_boundary` — Преломление на границе
- **waves** (Колебания и волны)
  - `harmonic_oscillations` — Гармонические колебания

**В Unity:** экран «главное меню» → список разделов → список установок → **загрузка префаба сцены** или **активация панели** с именем/id, совпадающим с таблицей выше.

## 5. Соответствие WPF → Unity (UI и отрисовка)

### 5.1 Слайдеры и ввод

- WPF: `Slider` + `Binding` к ViewModel  
- Unity: `UnityEngine.UI.Slider` или `Slider` в UI Toolkit; значения писать в тот же набор полей, что и во ViewModel WPF.

### 5.2 Анимация времени

- WPF: `DispatcherTimer` / таймер в ViewModel, обновление свойств → перерисовка  
- Unity: `Update()` / `FixedUpdate()` для физики; для «плавной анимации графика» — накопление точек с `Time.deltaTime`.

### 5.3 Графики (LiveCharts в WPF)

- В WPF: `LiveChartsCore.SkiaSharpView.WPF` — линии, оси, серии точек.  
- В Unity (варианты):
  - **Простой вариант:** массив `Vector2` → **LineRenderer** (масштабировать под Rect/камеру).
  - **UI:** рисовать в `Texture2D` / **RawImage** или использовать asset вроде **XCharts**, **Graph And Chart** (проверить лицензию).
  - Сохранить **те же оси и величины**, что в оригинале (подписи на русском по желанию).

### 5.4 Схемы установок (кастомные контролы с `DrawingContext`)

- Рисование линий, стрелок сил, блоков: в Unity — **Sprite** + **RectTransform**, или **LineRenderer** в мировых координатах, или один **Mesh** для статичной геометрии.  
- Координаты в WPF часто в «логических» единицах (метры условные) — **сохранить масштабирование** в одном месте (например, `float pixelsPerMeter`).

### 5.5 Тёмная тема

- WPF: фон `#1E1E1E`, панели `#252526`, акцент `#0E639C`.  
- Unity: задать те же цвета в **Theme ScriptableObject** или в префабах Canvas.

## 6. Чат Groq (опционально)

- Класс: `Services/GroqService.cs`, контекст: `Services/PhysicsChatContext.cs` (имя текущей установки).  
- В Unity: не хранить ключ в репозитории; для билда — **Remote Config** / пользовательский ввод / Editor-only.  
- Заменить `HttpClient` на `UnityWebRequest.Post` с JSON телом, если нужна совместимость с IL2CPP.

## 7. Рекомендуемая структура папок в Unity

```
Assets/
  Scripts/
    Physics/          ← порт классов из WPF Physics/
    UI/
      MainMenu/
      SetupList/
      Setups/         ← по одному контроллеру на setup id
    Navigation/       ← каталог разделов (как PhysicsCatalog)
    Services/         ← Groq и т.д.
  Prefabs/
    UI/
    Setups/           ← префаб на каждую установку (опционально)
  Scenes/
    Main.unity
```

## 8. Порядок миграции (чтобы не сломать зависимости)

1. Создать пустую сцену с **EventSystem** + **Canvas**.  
2. Перенести папку **`Physics/`** и убедиться, что проект компилируется.  
3. Реализовать **главное меню + список установок** по `PhysicsCatalog`.  
4. По одной установке: ViewModel-логика → MonoBehaviour, затем визуал, затем графики.  
5. В конце — Groq и полировка UI.

---

## 9. Чего избегать

- Не тянуть **WPF/XAML** в Unity — только идеи и **имена id**.  
- Не полагаться на **pixel-perfect** совпадение с WPF; важны **формулы и поведение**.  
- **LiveCharts** напрямую в Unity не используется — нужна замена (см. §5.3).

---

## 10. Краткий чеклист при генерации кода Unity

- [ ] Id разделов и установок совпадают с §3.  
- [ ] Логика расчётов вынесена в чистые классы без `MonoBehaviour`.  
- [ ] Один экран/префаб на setup id, переключение через каталог.  
- [ ] Графики: отображение массивов точек, согласованные подписи осей с физическим смыслом.  
- [ ] Кнопки: «Назад к списку», «Сброс», «Пуск/Стоп», «Объяснить» — по аналогии с WPF.  
- [ ] Сохранить смысл подсказок и формул из `PhysicsExplanationBuilder` (при переносе).
