# Как понять: какой метод в какой класс, когда создавать новый класс

## 1. Класс = одна сущность и её обязанности

Класс описывает **одну сущность** (или одну «роль») и содержит только то, что этой сущности логически принадлежит.

- **TaskItem** — это «одна задача». В нём: данные задачи (Id, Title, Tags, IsCompleted) и действия **над самой задачей**: `PrintInfo()`, `MarkCompleted()`.
- Методы вроде «добавить задачу в список», «найти по Id», «удалить из словаря» — это уже работа **со списком/хранилищем задач**, а не с одной задачей. Их место — в другом классе (или в Program как оркестрация).

Правило: **метод кладём в тот класс, объекты которого он по смыслу «меняет» или про которые «знает всё необходимое»**.

---

## 2. Когда создавать новый класс

Создавать отдельный класс имеет смысл, когда:

- Появляется **новая сущность** с собственными данными и поведением (Задача, Пользователь, Заказ).
- Появляется **отдельная роль/служба**: работа с файлами, с сетью, «менеджер задач», «валидатор ввода».
- Один класс **раздулся** и делает слишком разное — часть логики можно вынести в другой класс с чёткой ответственностью.
- Нужно **переиспользовать** одну и ту же логику в разных местах — выносим в отдельный класс (или статический класс с методами).

Не создавать класс «просто так»: если это один-два метода и они про текущую сущность — можно оставить в существующем классе.

---

## 3. Куда класть метод: четыре вопроса

Перед тем как написать метод, задай себе:

1. **Чьи данные он в основном использует?**  
   Если в основном поля одного объекта (например, одной задачи) — метод в класс этой сущности (например, `TaskItem`).

2. **Один объект или много?**  
   Работа с **одним** объектом (напечатать задачу, отметить выполненной) → метод у этого типа (`TaskItem`).  
   Работа со **списком/словарём** (найти по Id, отфильтровать, удалить из коллекции) → не в `TaskItem`, а в класс, который «владеет» коллекцией (менеджер/сервис), или в точку входа (`Program`).

3. **Может ли метод быть статическим?**  
   Если метод не использует поля экземпляра (`this`) — он может быть статическим в том же классе или в отдельном helper-классе (например, `InputHelper.ReadInt()`).

4. **Кто «владеет» операцией?**  
   «Отметить задачу выполненной» — меняет состояние **задачи** → `TaskItem.MarkCompleted()`.  
   «Удалить задачу из списка и словаря» — меняет **хранилище** → не в `TaskItem`, а в классе, который хранит список и словарь.

---

## 4. Пример на коде списка задач

| Метод | Чьи данные? | Один объект или много? | Куда класть |
|-------|-------------|------------------------|-------------|
| `PrintInfo()` | Одна задача (Id, Title, Tags, IsCompleted) | Один | **TaskItem** |
| `MarkCompleted()` | Одна задача (IsCompleted) | Один | **TaskItem** |
| «Найти по Id» | Словарь taskById | Много (поиск по коллекции) | Класс-хранилище или Program |
| «Удалить задачу» | List + Dictionary | Много | Класс-хранилище или Program |
| «Показать все» | List задач | Много | Класс-хранилище или Program |
| «Добавить задачу» | Создаёт TaskItem и кладёт в коллекции | Много | Класс-хранилище или Program |

Итого: **TaskItem** — только про одну задачу. Всё, что работает с коллекцией задач (добавить/удалить/найти в списке), живёт в другом месте: либо в `Program`, либо в классе типа `TaskManager` / `TaskRepository`.

---

## 5. Шпаргалка

- **Один объект, его данные и его состояние** → методы в класс этой сущности (например, `TaskItem`).
- **Работа с коллекцией, файлами, другим сервисом** → отдельный класс (менеджер, репозиторий, хелпер) или `Program`.
- **Несколько связанных полей и методов про одну концепцию** → выноси в отдельный класс.
- **Один маленький утилитный метод без состояния** → статический метод в подходящем классе или в маленьком helper-классе.
